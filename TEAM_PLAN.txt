HOW OUR AGENT WILL WORK (THE PLAN)
===================================

We decided on Strategy A: Enumerate the rule universe upfront, then refine with
streaming facts.

This is a small, predicate-agnostic ILP approach — not hand-coded transitivity
for "greater".


HIGH-LEVEL LOOP
---------------

1. Fact arrives → store in bounded memory
2. If new predicate P → generate ALL candidate rules for P (small finite set)
3. Compare new fact to stored facts → increment support for matching rule shapes
4. If fact is negative → eliminate rules that would derive it
5. When best rule's support plateaus → commit to LogicMemory.rules
6. Evict facts that become derivable (compression)
7. Answer quiz queries via Z3 entailment


STEP 1 — DEFINE A FINITE RULE UNIVERSE (HARDCODE SYNTAX, NOT SEMANTICS)
-----------------------------------------------------------------------

When predicate P first appears, generate all connected Horn clauses with at most
2 premises for binary relations. About 4–6 rules per predicate:

  P(X,Y) → P(Y,X)                          symmetry
  P(X,Y) ∧ P(Y,Z) → P(X,Z)                 chain / transitivity  ← expected on chain data
  P(X,Y) ∧ P(X,Z) → P(Y,Z)                 shared first arg
  P(X,Y) ∧ P(Z,Y) → P(X,Z)                 shared second arg

We do NOT hardcode "greater" or transitivity by name. The data selects which
shape wins.


STEP 2 — FACT PAIRS VOTE FOR CANDIDATES
---------------------------------------

When facts greater(5,4) and greater(4,3) are both in memory, they match the
chain pattern (shared middle: 4 at index 1 of first, index 0 of second). That
increments support for the chain rule.

On greater_chain_small with 9 adjacent facts, the chain rule gets ~8 supporting
pairs. Other shapes get little or no support.


STEP 3 — NEGATIVES ELIMINATE BAD RULES
--------------------------------------

Positives alone cannot kill wrong rules like symmetry — both are "consistent"
with greater(5,4).

We will add negative facts to the stream:

  not_greater(1, 2)    # 1 > 2 is false
  not_greater(1, 5)    # etc.

If symmetry derives greater(1,2) from greater(2,1), it gets eliminated.
Transitivity survives.


STEP 4 — COMMIT RULE WHEN SUPPORT PLATEAUS
------------------------------------------

  if support(best_rule) >= threshold and unchanged for K new facts:
      memory.add_rule(best_rule)
      evict derivable facts


STEP 5 — ANSWER QUERIES WITH Z3
-------------------------------

Same entailment loop as today in LogicMemory.ask:

  - Assert NOT query → if unsat, return "True"
  - Assert query → if unsat, return "False"
  - Otherwise → "Unknown"

We need to upgrade rule_to_z3 so committed rules use quantified or grounded FOL,
not propositional bools per fact.


WHY THIS IS GENERALIZABLE
-------------------------

Generalizable:
  - Rule universe works for any binary predicate
  - Same agent on greater_chain and divisibility_chain
  - Data selects the rule via support + negatives
  - One rule compresses many facts

Not generalizable:
  - if predicate == "greater": add transitivity
  - Separate logic per dataset
  - Manually inserting rules
  - Storing every fact

Test: Run the same FOLCompressionAgent on divisibility_chain_small with zero
code changes. It should learn divides(X,Y) ∧ divides(Y,Z) → divides(X,Z).

KEY DESIGN DECISIONS (FOR THE WRITE-UP)
---------------------------------------

1. Memory model: Separate bounded stores for facts and rules; FIFO eviction
   unless overridden by utility.

2. Reasoning: All query answering delegated to Z3 entailment.

3. Rule learning: Strategy A — finite predicate-agnostic hypothesis space,
   streaming refinement, support + negatives + plateau commit.

4. Generalization: We hardcode the logic fragment (Horn, binary, ≤2 premises),
   not domain rules.

5. Datasets: Fixed JSON files so all agents face identical benchmarks.


ONE-PARAGRAPH ELEVATOR PITCH
----------------------------

We built agents with limited memory that watch a stream of logical facts and
answer quiz questions. Simple baselines forget old facts and fail on questions
they never stored. Our FOL Compression Agent maintains a small universe of
candidate Horn-clause rules for each predicate it sees. As facts arrive, they
vote for rule shapes — and negative facts eliminate bad ones. When a rule's
support plateaus, the agent commits it, frees memory by evicting derivable
facts, and uses Z3 to answer questions requiring inference — like deriving
greater(10,5) from a chain of adjacent facts via transitivity. The same
mechanism learns the analogous rule for divides without any predicate-specific
code.
